# Design

## Context

`ScaleDisplay` сейчас: строка предупреждений, `ReadoutArea` с двумя `Box(weight(1f))` (таймер и вес занимают по половине свободной высоты), внизу `Metric("Поток")` у левого края. `ReadoutArea` через `BoxWithConstraints` и `TextMeasurer` считает общий масштаб шрифта от `constraints.maxHeight / 2`.

## Goals / Non-Goals

**Goals:** компактная центрированная группа без потери общего масштаба таймера и веса и без обрезания на узких экранах.

**Non-Goals:** менять формат значений, размер шрифта относительно друг друга, расположение кнопок и строки перегруза.

## Decisions

- **Группа вместо двух половин.** Вместо `Box(weight(1f))` на каждое значение — `Column(verticalArrangement = Arrangement.Center)` внутри `Box(contentAlignment = Center)`, между таймером и весом небольшой отступ (8 dp), под весом — поток.
- **Масштаб.** В `ReadoutArea` высота, от которой считается масштаб, становится `(maxHeight - потокИПодписи) / 2` вместо `maxHeight / 2`: группа теперь включает поток, и его высоту надо вычесть, иначе на низких экранах вернётся обрезание.
- **Поток** переносится внутрь группы и центрируется: `Metric` получает параметр выравнивания (`Alignment.Start` по умолчанию сохраняет поведение в других местах, если появится).

## Risks / Trade-offs

- [Меньше свободной высоты на масштаб → мельче цифры на низких экранах] → проверяем превью 640 dp и эмулятор 320 dp; при необходимости уменьшаем отступы группы, а не шрифт.
- [Вес визуально смещён влево на ширину единицы измерения] → центрируется строка «значение + единица» целиком, как сейчас; это обсуждалось в допущениях предложения.
