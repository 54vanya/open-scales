# Design

## Context

- Кнопки управления: `ControlButtons` в `ui/dashboard/DashboardScreen.kt`, колбэки идут в `ScaleViewModel` (`tare`, `toggleTimer`, `resetTimer`). Интерфейс уже меняется сразу при нажатии, без ожидания весов.
- Настройки: `SettingsActivity` → `SettingsScreen`, разделы «Устройство / Взвешивание / Действия». Все пункты завязаны на `ready` (весы подключены).
- На главном экране иконка настроек неактивна без выбранных весов (`enabled = state.address != null`), а раздел «Приложение» должен быть доступен всегда.
- Хранилище: DataStore Preferences `scale` (`SavedDeviceStore`), в нём только запомненное устройство.
- Звук весов (`0x07`, «Звук кнопок») — настройка самих весов, её не трогаем.

## Goals / Non-Goals

**Goals:**
- «Пик» звучит без заметной задержки (< 50 мс от нажатия) и не щёлкает.
- Никаких аудиофайлов в APK: тон генерируется из ноты.

**Non-Goals:**
- Вибрация и тактильный отклик.
- Звуки на другие события (подключение, окончание таймера).
- Произвольная частота или громкость, отдельная от системной.

## Decisions

### 1. Генерация тона: заранее подготовленные `AudioTrack` в режиме `MODE_STATIC`
Сигнал — синус 80 мс, 48 кГц, 16-bit моно, огибающая 5 мс вверх/вниз (без щелчков). Буфер PCM строится один раз для каждой ноты: 7 × ~7.7 КБ.
Для выбранной ноты держим готовый `AudioTrack` (`MODE_STATIC`, `PERFORMANCE_MODE_LOW_LATENCY`). Нажатие → `stop()` + `reloadStaticData()` + `play()`: сигнал стартует за единицы миллисекунд, а повторное нажатие перезапускает звук вместо наложения.
При смене ноты трек пересоздаётся.

*Альтернативы:*
- `ToneGenerator`: только DTMF и системные тоны, нужные ноты не выбрать.
- `SoundPool` с WAV-файлами: пришлось бы класть 7 файлов в APK, выигрыша нет.
- `MODE_STREAM` на каждое нажатие: создание трека добавляет 20–100 мс задержки.

### 2. Атрибуты звука: `USAGE_ASSISTANCE_SONIFICATION`, `CONTENT_TYPE_SONIFICATION`, без аудиофокуса
Так система сама глушит сигнал в беззвучном режиме и режиме вибрации, а громкость идёт по потоку системных звуков. Аудиофокус не запрашиваем, поэтому музыка не прерывается.

### 3. Модель настроек
```kotlin
enum class BeepNote(val label, val hz) { C6(1047), D6(1175), E6(1319), F6(1397), G6(1568), A6(1760), B6(1976) }
data class AppSettings(val beepEnabled: Boolean = true, val beepNote: BeepNote = BeepNote.A6)
```
Храним в том же DataStore `scale` под ключами `beep_enabled` и `beep_note` (имя enum). Новое хранилище `AppSettingsStore` — интерфейс с реализацией на DataStore и in-memory для тестов, по аналогии с `SavedDeviceStore`.

### 4. Где звучит сигнал
`Beeper` (синглтон в `OpenScalesApp`) подписан на `AppSettingsStore`. `ScaleViewModel.tare/toggleTimer/resetTimer` сначала вызывают `beeper.beep()`, затем команду. Кнопки неактивны без READY, поэтому неактивная кнопка звука не даст.
В UI звук не встраивается: так его можно проверить тестом ViewModel через фейковый `Beeper`.

### 5. UI настроек
- Раздел «Приложение» — первым в `SettingsScreen`, всегда активен.
- Переключатель (`Switch` в `SegmentedListItem`).
- Выбор ноты — горизонтальный ряд `ToggleButton` в connected button group (7 штук). Подписи короткие: «До», «Ре», «Ми», «Фа», «Соль», «Ля», «Си». При выборе — сохранение и пример сигнала.
- Иконка настроек на главном экране всегда активна. Без выбранных весов разделы весов скрыты, остаётся только «Приложение».

## Risks / Trade-offs

- [7 кнопок в ряд на узких экранах] → `ConnectedChoice` с `weight(1f)`, `maxLines = 1`. При ширине < 360 dp допустим перенос на `FlowRow`; проверить на эмуляторе 320 dp.
- [`PERFORMANCE_MODE_LOW_LATENCY` поддерживается не везде] → на API < 26 его нет, но minSdk 26. Если режим недоступен, система берёт обычный путь с задержкой ~30–50 мс, это допустимо.
- [Удержание `AudioTrack` расходует ресурсы] → один трек ~8 КБ. Освобождаем, когда звук выключен.
