# Design

## Context

Модель: `RecipeItem.Step(title, durationS, note, targetG, showTime)` и `Hint`. `Recipe.init` требует неубывающих `defaultTargetsG` по всему рецепту, `targetsG`/`totalWaterG` берут все цели подряд. `PourDistribution.fill(targets, weight)` раскладывает один вес по одному списку рубежей, `PourFocus.of(timeline, dose, weight, seconds)` выбирает шаг воды из всех целей. `BrewViewModel` тарирует весы только на «Старт»: `repository.withSession { tare() }`, затем `awaitingZero` → первый кадр `|w| < 1` становится опорой `PourDetector`. Налитое при варке — сырой вес весов (после тары «Старт» он от нуля). `StepsControls` после старта рисует «Пауза»/«Продолжить» и «Стоп», `PourBoard` — табло. Формат своего рецепта `RecipeFormat` версии 1, документы новее своей версии не читаются (`decode` → `null`).

Требования — в дельтах спек, мотивация — в proposal.md. Изменение строится поверх `recipe-editor-convenience` (заготовки, `increments()`, `duplicate()`, `summary()`).

## Goals / Non-Goals

**Goals:**
- Части рецепта считает чистый Kotlin (`recipe/`): вся арифметика частей покрыта юнит-тестами без Android.
- Рецепт без шагов «Тара» ведёт себя и выглядит ровно как раньше: эталоны варки не меняются.

**Non-Goals:**
- Замечать тару, нажатую на корпусе весов. По кадрам её не отличить от «сняли всё с весов», поэтому ноль части ставят только кнопки приложения.
- Тарировать автоматически: пользователь выбрал «по кнопке», потому что в начале шага на весах ещё стоит аэропресс или нет чашки.
- Переводить рецепт Литтла на тару: его «до 150 г» — вес напитка с концентратом, а не налитая вода.

## Decisions

### Шаг «Тара» — признак шага, а не новый вид элемента

`RecipeItem.Step.tare: Boolean = false` (и `DraftItem.Step.tare`), `init` требует у шага с `tare` пустых `targetG` и `showTime`. Шаг «Тара» занимает время, стоит в `RecipeTimeline`, у него название, длительность и комментарий — всё как у шага. Отдельный `RecipeItem.Tare` потребовал бы ветки в каждом `when` по элементам (таймлайн, список, предпросмотр, черновик, формат) ради того же набора полей.

Альтернатива — признак «тара перед шагом» у шага с водой («Разбавьте» с тарой в начале). Отклонена: время на то, чтобы снять аэропресс, пришлось бы прятать в длительность пролива, а кнопке тары нужен свой шаг на табло.

### Части рецепта

`Recipe.partOf: List<Int>` — часть каждого элемента `items`: шаги с `tare` открывают новую часть (шаг «Тара» — первый элемент своей части), `partCount` — число частей. Рядом:
- `targetsByPart(doseG): List<List<Pair<Int, Double>>>` — индекс шага и цель при дозе;
- `totalWaterG(doseG)` — сумма последних целей частей (заменяет «последнюю цель»);
- `init` проверяет неубывание внутри каждой части.

`defaultTargetsG` и `targetsG` остаются плоскими (все цели подряд) для мест, где части не важны; `totalWaterG` и распределение переходят на части. `RecipeTimeline.partAt(seconds)` — часть, где идёт время. Для рецепта без тары одна часть — поведение прежнее, это проверяют существующие `RecipeTest`/`PourFocusTest`.

### Варка: состояние частей в ViewModel

`TareState` (чистый Kotlin в `recipe/`) хранит `zeros: Map<part, Double>` — нули оттарированных частей (у части 0 ноль после «Старт») — и `frozen: Map<part, Double>` — сырой вес, на котором часть застыла. `pouredIn(part, weight)` — налитое в часть: `(frozen[part] ?: weight) − zero`, у части без нуля — 0. `BrewViewModel` держит его в своём состоянии: переход времени в часть `k` вызывает `freezeBefore(k, lastWeight)`, тара на части — `tared(k, zero)`. `BrewUi` получает `tare`, `tareBusy` и `awaitingTare` (часть, где идёт время, без нуля; время рецепта не кончилось).

`tareStep()` повторяет ветку «Старт»: `repository.withSession { tare() }`, затем первый кадр `|w| < 1` становится нулём части. Повторное нажатие, пока ждём, игнорируется. Ошибка — `commandErrorRes` в `errors`, состояние не меняется.

`PourDistribution.values(recipe, dose, pouredIn, mode)` раскладывает воду по частям: у каждой свои рубежи `Recipe.targetsByPart` и свой вес `tare.pouredIn(part, weight)`. `PourFocus.of(..., tare)` выбирает шаг воды только в части, где идёт время, и возвращает `null`, пока она ждёт тары, — недолитое в прошлых частях не переносится.

### Кнопки

- `PourBoard`: при `awaitingTare` вместо `BigReading` воды — `FilledTonalButton` высотой с крупное число, текст «Тара» стилем показаний, под ним `BoardCaption` с комментарием шага «Тара» этой части. Высота табло не меняется.
- `StepsControls`: при `ui.started && ui.awaitingTare` в ряду перед «Пауза» — `FilledTonalButton` «Тара» с тем же `rememberPressAction`, вес 1f. На 320 dp три кнопки уже есть до «Старт» («Тара», «Старт», «Стоп»), так что ряд помещается.
- Обе вызывают `viewModel.tareStep()`, доступны при `scale.isReady && !tareBusy`.

### Формат

`ItemDto.Step.tare: Boolean = false` пишется только при `true`, как `showTime`. `RecipeFormat.VERSION = 2`, но `encode` пишет `format = 2` только если у рецепта есть шаг «Тара», иначе 1. Старое приложение (VERSION 1) такой документ пропустит, а не прочтёт без тары с «убывающими» рубежами и не упадёт в `init`. `decode` принимает 1 и 2.

### Редактор

Заготовка `ItemTemplate.TARE` → `Step(title = "Тара"/«Tare» из ресурса, duration «015», tare = true)`. `ExpandedItem` для шага с `tare` не рисует поле рубежа и переключатель, иконка заголовка — `Icons.Rounded.Scale`. `StepCard` получает `isTare` → иконка весов справа вместо рубежа (и в варке, и в редакторе). `increments()`, `duplicate()`, `validate()` и `summary()` сбрасывают «рубеж выше» на шаге с `tare`. При разборе `toRecipe()` у шага «Тара» рубеж и признак времени не переносятся, даже если в черновике были (черновик из заготовки их не имеет, но так надёжнее).

## Risks / Trade-offs

- [Пользователь нажал тару на корпусе весов] → часть не считается оттарированной, кнопки остаются; вес части при этом начнёт считаться после нажатия в приложении (ещё одна тара на нуле ничего не портит). Описать в подсказке шага «Тара» по умолчанию не будем — комментарий пишет автор.
- [Тара во время прожима: руки давят на весы] → решает автор рецепта, где поставить шаг «Тара»; во встроенном — после «Прожмите».
- [Связь пропала на шаге «Тара»] → кнопки неактивны, как «Тара» до «Старт»; после переподключения доступны снова, время идёт.
- [Два чейнджа меняют одни требования] → `recipe-tare-step` архивируется только после `recipe-editor-convenience`; его MODIFIED-блоки построены на версии из первого чейнджа.
