# Design

## Context

Material `Button` вызывает `onClick` по отпусканию. События касания доступны через `MutableInteractionSource` кнопки (`PressInteraction.Press / Release / Cancel`), который уже используется для анимации ширины в `ButtonGroup`.

## Goals / Non-Goals

**Goals:** срабатывание по касанию без потери визуальной обратной связи Material (ripple, морфинг формы) и без поломки доступности.

**Non-Goals:** удержание (long-press), автоповтор, отдельные режимы для разных кнопок.

## Decisions

- **`rememberPressAction(interactionSource, enabled, action)`** слушает `PressInteraction.Press` и выполняет действие; возвращает колбэк для `onClick`, который пропускает действие, если оно уже выполнено касанием (флаг `AtomicBoolean`, сбрасывается на `Cancel`). Так TalkBack/клавиатура, которые вызывают click без Press, продолжают работать, а обычное касание не даёт двойного срабатывания.
  *Альтернатива:* `pointerInput { detectTapGestures(onPress) }` поверх кнопки — ломает ripple/морфинг и семантику click.
- **Режим «При отпускании»** = тот же хелпер с `enabled = false` для Press, т.е. стандартный `onClick`.
- **Хранение**: `AppSettings.triggerOnPress` (по умолчанию `true`), DataStore-ключ `trigger_on_press` рядом с настройками звука.
- **UI**: первая строка раздела «Приложение», connected button group из двух вариантов.

## Risks / Trade-offs

- [Касание при начале прокрутки] → на главном экране нет прокручиваемого контейнера, поэтому `Press` приходит сразу и ложных срабатываний от скролла нет. Если экран станет прокручиваемым, Compose задержит `Press` (tap timeout), и поведение нужно перепроверить.
- [Случайное касание в режиме «При касании» нельзя отменить уводом пальца] → осознанно: так ведут себя кнопки весов; для тех, кому это мешает, есть режим «При отпускании».
