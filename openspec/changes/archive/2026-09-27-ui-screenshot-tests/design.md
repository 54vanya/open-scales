# Design

## Context

UI — Compose, экраны — функции с состоянием в параметрах (`StepsScreen(ui = ...)`, `RecipeEditorScreen(ui = ...)`), поэтому их можно рисовать без Activity и ViewModel. Юнит-тесты идут на JVM; эмулятор в CI не нужен и нежелателен.

## Goals / Non-Goals

**Goals:**
- Одобренный вид проверяется сам при каждой полной проверке, без эмулятора и без участия Claude.
- Поломка видна наглядно: эталон, разница, новое.

**Non-Goals:**
- Скриншоты на реальных размерах всех телефонов и во всех темах — только основной телефон, узкий экран там, где он обсуждался.
- Проверка анимаций — только установившиеся состояния.

## Decisions

### Roborazzi на Robolectric

Выбран пользователем из трёх вариантов. В отличие от Compose Preview Screenshot Testing, умеет нажимать и снимать окна поверх экрана (диалоги), а в отличие от Paparazzi — работает через Robolectric и не зависит от layoutlib конкретной версии AGP.

### Окружение снимков

`ScreenshotTest` задаёт: `GraphicsMode.NATIVE` (настоящая отрисовка), простой `Application` (иначе `OpenScalesApp` поднимал бы Bluetooth и хранилища), `OpenScalesTheme(dynamicColor = false)` светлую, `ru-w411dp-h914dp-xxhdpi`; узкий — `ru-w320dp-h780dp`. Экраны с окнами поверх снимаются `captureScreenRoboImage`, остальные — `onRoot().captureRoboImage`.

### SDK 34

Robolectric 4.17 для SDK 35+ требует Java 21, проект собирается на Java 17. Для отрисовки Compose версия платформы не важна.

### Встраивание в проверку

`verifyRoborazziDebug` запускает все юнит-тесты и сверяет снимки; им заменён `testDebugUnitTest` в полной проверке. `recordRoborazziDebug` перезаписывает эталоны — только после того, как новый вид одобрен и просмотрен.

## Risks / Trade-offs

- [Шрифты и сглаживание на другой машине могут дать крошечные отличия] → эталоны пишутся и сверяются на одной машине; если понадобится CI, добавить порог сравнения Roborazzi.
- [Эталон закрепит ошибку, если записать его, не посмотрев] → правило в `CLAUDE.md`: перед записью эталон просмотреть глазами.
