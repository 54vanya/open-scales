## Context

`BleJournal` — один кольцевой буфер на 2000 записей в памяти процесса. Кадры веса пишутся как `RX` ~10 раз в секунду,
тики секундомера как `TIMER` раз в секунду, поэтому всё остальное живёт в буфере около 3 минут. Запись идёт из разных
потоков (главный, binder-колбэки через `LoggingBleTransport`, поток сторожа) под `synchronized`. Всё это — только debug:
в release `bleJournal == null`.

## Goals / Non-Goals

**Goals:**
- Редкое событие (`STALL`, опоздавший тик, пауза в кадрах, разрыв) остаётся доступным часами, пока жив процесс.
- Паузы в потоке кадров видны без чтения тысяч строк RX.

**Non-Goals:**
- Запись журнала в файл и переживание перезапуска процесса.
- Исправление самих подвисаний: это следующий шаг, когда будут данные.
- Любые изменения release-сборки.

## Decisions

- **Второй буфер вместо фильтра по одному.** Важность — свойство записи при добавлении: `add(kind, text, notable)`,
  по умолчанию определяется видом (`TX`, `RX`, `TIMER` — не важные, остальные — важные). Запись кладётся в общий буфер и,
  если важна, в буфер важных на 500 записей. Альтернатива «не писать RX в общий журнал» теряет то, ради чего журнал
  делался — сверку кадров.
- **Порог опоздания тика — 100 мс.** Тик планируется на край секунды, обычное опоздание — единицы миллисекунд; 100 мс —
  уже заметный на глаз сдвиг и заведомо не шум планировщика. Решение принимает тот, кто пишет тик (`OpenScalesApp`),
  журнал про секундомер не знает.
- **`GAP` замеряет `LoggingBleTransport`.** Он и так видит каждое уведомление. Считаем только характеристику протокола
  2025: весы присылают туда вес сами ~10 Гц, пауза там — сбой. Legacy-весы шлют indicate не по расписанию, для них пауза
  ничего не значит. Время — `SystemClock.elapsedRealtime` через параметр (в тестах — свои часы). Отсчёт сбрасывается при
  разрыве, чтобы промежуток между сессиями не считался паузой. Порог 300 мс: при `HIGH` промежутки 90/120 мс, при
  `BALANCED` бывают ~390 мс — это тоже стоит видеть.
- **Экран: переключатель в верхней панели** (иконка фильтра), подзаголовок показывает число записей текущего вида. Экспорт
  — обе части с заголовками разделов.

## Risks / Trade-offs

- Замер паузы идёт по времени доставки в `events` (после binder-потока и flow), а не по радио — он включает и задержку
  доставки внутри процесса. Для поиска подвисаний это даже полезно: пауза без `STALL` укажет на связь, с `STALL` — на
  приложение.
- Лишняя память — до 500 коротких строк, только в debug.
