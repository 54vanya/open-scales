# Design

## Context

`PourBoard` рисует ветки табло: итог, кнопка «Тара», время крупно, вода (по `PourFocus`) и пустое табло до «Старт» (содержимое раскладывается невидимым, чтобы высота не менялась). `PourFocus` знает индекс шага воды, его цель и остаток `leftG`, но не цель шага выше. Цели по частям даёт `Recipe.targetsByPart`, налитое в часть — `TareState.pouredIn` (из `recipe-tare-step`).

## Goals / Non-Goals

**Goals:**
- Долю считает чистый Kotlin рядом с `PourFocus`, экран только рисует.
- Табло не прыгает по высоте при переходе вода ↔ время ↔ тара.

**Non-Goals:**
- Метка «где должен быть налив к этой секунде»: выбрано «только вода».
- Полосы в карточках шагов списка: там уже есть число шага.

## Decisions

### Доля в `PourFocus`

`PourFocus` получает поле `previousG` — цель шага выше в части (0 у первого), и свойство `fraction`: `((targetG − leftG) − previousG) / (targetG − previousG)`, ограниченное 0..1; при `targetG <= previousG` — 1, если цель набрана (`state != BELOW`, как у сигнала цели), иначе 0. `targetG − leftG` — это уже налитое в часть, так что тара и связь учитываются тем же путём, что у крупного числа.

Альтернатива — считать долю из `PourDistribution` по индексу шага. Отклонена: табло уже опирается на `PourFocus`, и две разные функции могли бы разойтись в запоздалом проливе.

### Полоса

`LinearProgressIndicator(progress = { fraction })` из Material 3 — без собственной анимации (лямбда читается на каждой отрисовке, значение не интерполируется). Цвет — `colorScheme.primary`, при `TargetState.OVER` — `colorScheme.error`; трек — `outlineVariant` (`surfaceVariant` в светлой теме сливается с фоном табло). Толщина 24 dp, отступ сверху 10 dp. В остальных ветках табло — тот же `LinearProgressIndicator` с `alpha(0f)`: место занято, как у пустого табло до «Старт».

Волнистый `LinearWavyProgressIndicator` из Expressive не берём: волна движется сама и спорит с правилом «показания не анимируются».

## Risks / Trade-offs

- [В альбомной раскладке табло невысокое] → полоса 24 dp + отступ; крупное число уже ужимается (`weight(1f, fill = false)`), проверить поворотом на эмуляторе.
- [Цель шага равна цели выше (копия без прибавки)] → полоса пустая до цели и полная после, без деления на ноль.
