# Design

## Context

Черновик (`RecipeDraft`, `DraftItem`) — чистый Kotlin со строковыми полями, как их ввёл человек. Экран (`RecipeEditorScreen`) получает `EditorUi` и вызывает `EditorActions`. `EditorActions.insert(index, step: Boolean)` вставляет пустой `DraftItem.Step(key)` или `DraftItem.Hint(key)`, `RecipeEditorViewModel.insert` раскрывает новый элемент. Строк Android у ViewModel нет: тексты встроенных рецептов в черновик переводит Activity через `toDraft(resolve)`. Свёрнутый шаг рисует общая `StepCard` из `ui/recipes`, справа у неё рубеж строкой `target`. Скриншот-тесты: `snapshot()` снимает корень Compose, `screen()` снимает все окна (попапы, диалоги).

## Goals / Non-Goals

**Goals:**
- Вся логика заготовок, копии, прибавок и сводки — функции черновика в `recipe/`, покрытые `RecipeDraftTest`. Экран только показывает результат.
- Модель `Recipe`, формат JSON и экран варки не меняются.

**Non-Goals:**
- Вводить рубеж прибавкой. Поле остаётся накопительным, прибавка только показывается.
- Дублировать группу элементов (пару «налейте + подождите»). Дублируется один элемент.
- Запоминать, из какой заготовки создан шаг. После вставки это обычный шаг.

## Decisions

### Заготовки — перечисление в черновике, название передаёт экран

`enum class ItemTemplate { POUR, WAIT, ACTION, HINT }` в `RecipeDraft.kt` и `fun ItemTemplate.newItem(key: Long, title: String): DraftItem`: для POUR — `Step(title, showTime = false)`, для WAIT — `Step(title, showTime = true)`, для ACTION — `Step("", showTime = true)`, для HINT — `Hint`. Название («Налейте»/«Подождите») берёт экран из ресурсов (`recipe_step_pour`, `recipe_step_wait`: те же слова, что во встроенных рецептах) и передаёт в `EditorActions.insert(index, template, title)`. Так ViewModel по-прежнему не знает о ресурсах, а текст вставляется на языке интерфейса как `Plain` и дальше не переводится (как у копии встроенного рецепта).

Альтернатива: хранить в черновике `Text.Res` до сохранения. Отклонена: черновик держит строки, и смена языка во время правки превратила бы слово в чужое.

### Фокус в поле рубежа у «Пролива»

В `EditorUi` появляется одноразовое `focusTarget: Long?`. `insert` с POUR ставит его на ключ нового шага. `ExpandedItem` для шага с этим ключом вешает `FocusRequester` на поле рубежа и в `LaunchedEffect` вызывает `requestFocus()`, затем `actions.focusConsumed()`. Список перед этим прокручивается к новому элементу (`editorListIndex`), иначе элемент вне экрана не скомпонован и фокус некуда ставить. При повороте экрана `focusTarget` уже сброшен, поэтому фокус повторно не прыгает.

### «Повторить»: копия со сдвигом рубежа

`RecipeDraft.duplicate(key, newKey): RecipeDraft` вставляет копию сразу после элемента. Прибавку считает общий помощник `RecipeDraft.increments(): Map<Long, Int>`: для каждого шага с разобранным рубежом `t` — `t − p`, где `p` — ближайший разобранный рубеж выше (или 0). Отрицательные прибавки не включаются. Копия шага получает `targetG = (t + inc).toString()`, если прибавка есть, иначе поле как есть. ViewModel раскрывает копию, не трогая раскрытость исходного элемента.

Почему сдвиг, а не тот же рубеж: копия с тем же рубежом — пролив на 0 г, её рубеж всё равно придётся править. Серия 60/120/180 (4:6, «одна чашка», Хсу) набирается без клавиатуры.

Кнопка — иконка `ContentCopy` в заголовке раскрытой карточки между «Ниже» и «Удалить». На 320 dp в строке остаются иконка вида, слово «Шаг»/«Заметка» и четыре кнопки по 48 dp — проверяется эталоном `editor_narrow` с раскрытым шагом.

### Прибавка у свёрнутого шага

`StepCard` получает необязательный `targetIncrement: String?`, строка мелко (`labelMedium`, приглушённый цвет) под `target`. Экран варки его не передаёт — там вид не меняется, и эталоны варки остаются прежними. Значения из `increments()` форматируются в целые граммы через `value_with_unit` с плюсом.

### Сводка

`RecipeDraft.summary(): DraftSummary(waterG: Int?, ratio: Double?, totalS: Int)`: вода — последний разобранный рубеж, соотношение — `waterG / dose`, если доза разобрана и больше нуля, время — конец `times()`. Строку собирает экран: `formatTime`, соотношение через `NumberFormat` локали с `maximumFractionDigits = 1` (даёт «16,7» по-русски, «16.7» по-английски и «15» без «,0»). Строка — последний элемент `RecipeCard`, `bodyMedium`, `onSurfaceVariant`.

### Вид шага вместо переключателя

`RecipeItem.Step.showTime` перестаёт быть полем: `val showTime get() = targetG == null && !tare`. Табло, прогресс-бар и тесты читают то же свойство, поэтому поведение варки встроенных рецептов не меняется (`BuiltInRecipesTest` и так требовал равенства). `ItemDto.Step.showTime` остаётся в DTO только для чтения старых документов и игнорируется; при записи его нет.

В черновике — `DraftItem.Step.kind: StepKind { POUR, ACTION, TARE }` вместо `showTime`/`tare`. `toDraft` выводит вид из рецепта (есть `tare` → TARE, есть цель → POUR, иначе ACTION), `toRecipe` у ACTION и TARE не переносит воду. `validate` добавляет `EMPTY` для воды пролива. Заготовки задают вид; `duplicate` копирует вид.

Почему вид нельзя сменить у готового шага: выбор вида в заголовке карточки — тот же переключатель под другим именем, а путал именно он. Ошибка вида исправляется удалением и новой заготовкой; название и комментарий короткие.

## Risks / Trade-offs

- [Свой рецепт со старым шагом «без воды и без отсчёта» начнёт показывать отсчёт] → таких шагов нет во встроенных; у своих это и было задумано почти всегда. Сценарий «Признак выводится из воды».
- [Сдвинутый рубеж копии больше рубежа шага ниже] → так задумано, ошибка «меньше рубежа выше» появится у нижнего шага при «Сохранить», как при ручном вводе. Автоматически сдвигать нижние рубежи не будем: это молча меняет чужие числа.
- [Четыре иконки в заголовке на узком экране] → слово вида может сжиматься; проверяется узким эталоном.
- [Фокус и клавиатура в момент анимации раскрытия] → `requestFocus` после появления поля в `LaunchedEffect`, список уже подтягивает поле в фокусе над клавиатурой (есть в «Экране редактора»).
