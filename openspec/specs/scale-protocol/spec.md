# scale-protocol Specification

## Purpose
Описывает бинарный BLE-протокол весов Timemore Black Mirror: как приложение кодирует команды и декодирует ответы и уведомления весов.

## Requirements

### Requirement: Формат кадра протокола 2025
Приложение SHALL кодировать каждую команду для весов TES015/TES016/TES017 как кадр `A5 5A | type | cmd | len(2 байта, BE) | payload | crc(2 байта, BE)`, где `type = 0x02` для чтения (payload пустой), `type = 0x03` для записи, а `crc` — CRC-16/Modbus (init `0xFFFF`, poly `0xA001`) по всем предыдущим байтам кадра. Кадры SHALL записываться в характеристику `0000fff2-0000-1000-8000-00805f9b34fb` сервиса `0000fff0-…`.

#### Scenario: Кадр чтения батареи
- **WHEN** приложение запрашивает чтение команды `0x05`
- **THEN** в характеристику записывается `A5 5A 02 05 00 00` и два байта CRC-16/Modbus от этих шести байт

#### Scenario: Кадр записи тары
- **WHEN** приложение отправляет тару
- **THEN** записывается кадр `A5 5A 03 0D 00 02 00 00` + CRC

### Requirement: Разбор входящего потока
Приложение SHALL искать в каждом уведомлении с `FFF1` все вхождения заголовка `A5 5A`, выделять кадры длиной `len + 8`, игнорировать кадры с неверной длиной (`len > 1024` или обрезанный кадр) и обрабатывать несколько кадров в одном уведомлении.

#### Scenario: Два кадра в одном уведомлении
- **WHEN** приходит уведомление, содержащее подряд кадр веса и кадр таймера
- **THEN** приложение обновляет и вес, и состояние таймера

#### Scenario: Обрезанный кадр
- **WHEN** длина из заголовка превышает оставшиеся байты уведомления
- **THEN** кадр отбрасывается без ошибки, предыдущие кадры обработаны

### Requirement: Подтверждения записи
Кадр с `type = 0x03` SHALL трактоваться как подтверждение записи для команды `cmd`; первый байт payload `0x01` означает успех, любое другое значение — отказ устройства.

#### Scenario: Весы отклонили команду
- **WHEN** приходит `type=0x03, cmd=0x07, payload=[0x00]` на ожидающую запись звука
- **THEN** операция завершается ошибкой «устройство отклонило команду»

### Requirement: Декодирование данных весов
Приложение SHALL декодировать payload следующих команд:
- `0x01` вес: int32 BE вес, int16 BE скорость потока, uint16 BE время в секундах, опционально байт перегруза; делитель 10 для граммов и 100 для унций;
- `0x02` таймер: `1` — идёт, `2` — пауза, `3` — сброшен;
- `0x05` батарея: уровень в процентах и признак зарядки;
- `0x06` единицы: `0` — граммы, `1` — унции;
- `0x07` звук: `0/1`;
- `0x0C` имя (UTF-8), `0x10` версия прошивки, `0x12` серийный номер (ASCII);
- `0x13` модель: `TES015` → ESPRO, `TES016` → Basic 3, `TES017` → DOT;
- `0x16` авто-отключение: uint16 BE секунды;
- `0x17` чувствительность: уровень во втором байте (1 — высокая, 2 — средняя, 3 — низкая);
- `0x18` точность: `1` — высокая, `10` — низкая;
- `0x25` яркость: 0..100.

#### Scenario: Вес в граммах
- **WHEN** единицы — граммы и приходит кадр `0x01` с весом `0x000004D2`, скоростью `0x0019`, временем `0x000F`
- **THEN** отображается вес 123.4 г, поток 2.5 г/с и время 00:15

#### Scenario: Отрицательный вес
- **WHEN** int32 веса равен `0xFFFFFFF6`
- **THEN** вес декодируется как −1.0 г

### Requirement: Legacy-протокол TES08
Для весов, у которых есть сервис `0000181d-…`, приложение SHALL подписываться на indicate характеристики `00002a9d-…`, декодировать общий вес как int32 LE из байт 1..4 (делитель 10) и отправлять команды в `553f4e49-bf21-4468-9c6c-0e4fb5b17697` в виде `[cmd] + payload` (тара `0x00`, старт `0x08`, пауза `0x09`, сброс `0x0A`, звук `0x10`, имя `0x0B len bytes`).

#### Scenario: Вес с TES08
- **WHEN** приходит indicate `10 D2 04 00 00 …`
- **THEN** отображаемый вес равен 123.4 г
